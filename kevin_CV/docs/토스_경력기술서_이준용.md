## [상세 경력 사항]

### 1. PI SpeedLAB, INC. (근무 기간: 2025.10.22 ~ 재직 중 / 직급: 대표이사 · 기술총괄)

- **주요 사업**: 스마트폰 결합형 도플러 스피드레이더 `PI-Link` — 하드웨어 + 앱 + 데이터 플랫폼
- **소속 / 직책**: 대표이사 겸 기술총괄 (창업자, 미국 법인)

#### [주요 프로젝트 및 성과]

**① 프로젝트명: 초도양산 · 4개국 전파인증 · 글로벌 배포 프로젝트**

- **프로젝트 개요**: 실측 검증을 마친 PI-Link의 양산 전환과 FCC·KC·CE·TELEC 인증, 베타 배포까지의 제품화 품질 책임
- **담당 역할**: 제품 총괄 (개발 품질 · 인증 · 배포)
- **주요 수행 업무 (액션)**
  - 신호 품질 · 전송 안정성 검증 결과를 설계에 반영한 **초도양산 600대** 진행
  - 4개국 전파인증 시험 항목 정의 → 적합성 미달 항목 원인 분석 및 설계 수정 반복
  - 베타 배포 운영(누적 다운로드 **500**) 및 정식 출시 준비 — 출시 전 회귀 체크리스트화
- **정량적 성과 (임팩트)**
  - **FCC·KC·CE·TELEC 4개국 인증 통과**, 초도양산 600대 완료
  - 배포 전 검증 체계화로 인증 심사 · 양산 품질 리스크 최소화

**② 프로젝트명: 모바일 엣지 AI · 저대역폭 전송 산학 공동연구 (경기RISE, 2026.06 ~ 2026.11)**

- **프로젝트 개요**: 경희대학교 산학협력단 · AE Lab(지도 교수 김상혁) 공동연구 — 스피드 레이더의 저대역폭 신호 전송 및 실시간 속도 추출 기술 개발 (기여도 **85%**)
- **담당 역할**: 앱 · 통신 개발 리드 (BLE 스택 · 검증 파트)
- **주요 수행 업무 (액션)**
  - **BLE 스택 튜닝(Renesas DA14531)**: notification + 509바이트 분할 전송으로 대용량 패킷 수신 문제 해결
  - 집중 전송 시 발생하는 레이더 노이즈 간섭을 **스펙트로그램 분석으로 규명 → 전송 시점 분산**으로 제어
  - iOS에서 데이터가 충분히 전달되지 않는 이슈를 로그 분석으로 원인 규명 후 재설계, Python 도플러 분석 도구(파워 스펙트럼 · 스펙트로그램 · CFAR)로 실측 기반 반복 검증
  - AE Lab과 **CFAR 파라미터 튜닝**, 회로부터 신호 처리까지 단계별 원인 분리 · 반복 검증
- **정량적 성과 (임팩트)**
  - **iOS BLE 실효 전송속도 210kbps** 확보 (목표 미달 → 원인 분석 · 해소)
  - 전송 데이터율 **240kbps → 110kbps** 최적화, **Noise Floor 8dB 개선**
  - 탐지 거리 **2m → 5m**, 투구 1,000회 기준 **미탐율 7% → 1% 미만, 과검출률 6% → 1% 미만**

**③ 프로젝트명: 글로벌 고객 검증 및 플랫폼 제휴 (CES / Kickstarter / UNIDEN)**

- **프로젝트 개요**: 제품-시장 적합성(PMF)을 글로벌 채널로 검증하고 라이선스 파트너 확보
- **담당 역할**: 대표 (해외 사업 · 고객 대응 · 기술 설명)
- **주요 수행 업무 (액션)**

  - 미국 유소년 야구 · 소프트볼 시장 고객 인터뷰 **50건** 수행 → 요구사항을 제품 방향에 반영
  - 레이더 전문기업 **UNIDEN과 NDA 체결**, 라이선스 생산 협의 진행
- **정량적 성과 (임팩트)**

### 2. 카이큐테크 CaiqueTech (근무 기간: 2024.05.22 ~ 2025.01.01 / 직급: 개발부 공동대표)

- **주요 사업**: PI-Link(스마트폰 연동 스피드레이더) 제품 개발
- **소속 / 직책**: 개발부 공동대표 — 공동 창업 · 기술 담당

#### [주요 프로젝트 및 성과]

**① 프로젝트명: 하드웨어–앱 엔드투엔드 연결 플랫폼 개발** ⭐ *(핵심 차별 경력)*

- **프로젝트 개요**: 24GHz 도플러 레이더 모듈과 스마트폰 앱을 USB-C·BLE로 연결하는 종단간 연결 스택 개발 — **기기 펌웨어, 통신 프로토콜, 앱 UX까지 한 사람이 끝까지 책임진 프로젝트**
- **담당 역할**: 메인 개발자 (펌웨어 · 통신 · Android/iOS 앱 전 구간)
- **주요 수행 업무 (액션)**
  - **STM32F373 MCU 펌웨어**: DMA/Ring Buffer 기반 20kHz 도플러 신호 수집, Delta 무손실 · ADPCM 손실 압축 구현
  - **앱 개발**: **Kotlin(Android) · Swift(iOS) 네이티브 카메라 모듈** 직접 구현으로 각 기기에서 **고속 촬영 · 촬영 오버레이** 지원, 실시간 속도 표시 · 기록 저장 · 날짜별 분석 UX 설계
  - **멀티 디바이스 대응**: 센서 · 회로 리비전 조합을 모듈형 연결 계층으로 추상화 — 연결 문제를 디바이스별이 아닌 계층으로 해결
  - **UI/UX**: 측정 중에도 한눈에 읽히는 실시간 화면 구조 설계, 오프라인 현장(구장 · 전시회)에서 네트워크 없이 동작하도록 로컬 저장 · 분석 구조 적용
- **정량적 성과 (임팩트)**
  - **등록 특허 2건**(10-2674614 · 10-2861127) — 하드웨어–앱 결합 구조를 IP로 확보
  - 센서 · 회로 리비전 변경에 강한 **모듈형 연결 계층** 구축 → 디바이스 확장 시 앱 재작업 최소화
  - 실시간 속도 측정 · 영상 기록 · 날짜별 분석 앱 완성 → 후속 베타 배포(500)의 기반 마련

**② 프로젝트명: 실기기(HIL) 검증 자동화로 개발 · 검증 주기 단축**

- **프로젝트 개요**: 하드웨어와 앱을 동시에 바꿀 때마다 발생하던 수작업 검증 · 재현 문제 해결
- **담당 역할**: 검증 환경 설계 · 자동화 담당
- **주요 수행 업무 (액션)**
  - **PCB · 스마트폰 · PC · J-Link 연결 HIL 폐루프** 검증 환경 구축
  - 펌웨어 빌드 · 업로드를 스크립트로 자동화, 실기기 수신 상태 · 전송 속도를 반복 측정
  - 목표 미달 시 로그를 분석해 설정을 수정하고 변경 전후 결과를 비교하는 사이클 운영
- **정량적 성과 (임팩트)**
  - 변경 전후 성능을 **숫자로 판정하는 회귀 검증 체계** 확립 → 하드웨어 · 앱 동시 변경 프로젝트의 품질 리스크 관리
  - 측정 · 분석 자동화로 외부 의존 없이 하루 단위 반복 검증 가능

## [지원 동기] — 토스플레이스 Android Developer

- **"앱이 하드웨어를 직접 제어해본 개발자"라는 경력이 토스플레이스와 정확히 맞습니다.** POS · 단말처럼 **디바이스 사이의 연결 UX와 연결 안정성**을 다루는 로컬연결 Team의 문제(불안정한 링크에서도 끊기지 않는 연결)는 제가 PI-Link에서 BLE · 펌웨어 · 앱 전 구간을 책임지며 풀어온 문제와 동일합니다.
- **OS · 펌웨어와의 협업, 멀티플랫폼 SDK** — MCU 펌웨어를 직접 쓰고 BLE 스택을 튜닝하면서, 앱 한 쪽만 바꾸면 안 되는 문제가 어떻게 전체 성능을 좌우하는지 체감했습니다. 문제를 계층으로 나눠 원인 분리 · 검증하는 방식(HIL · 자동화)을 몸에 익혔습니다.
- **품질과 안정성에 대한 끈질긴 책임감**: 미탐율 7%→1% 수준의 개선을 "끝까지" 추적했고, 검증 결과를 숫자로 공유하는 방식으로 팀의 판단 근거를 만들겠습니다. Kotlin 기반 코드베이스의 품질 · 생산성 개선과 TDS를 활용한 인터랙션 구현은 빠르게 학습해 기여하겠습니다.
